LMFDB version numbers have the form {major}.{data}-{code} (for example 2.3-5):

  • major is incremented by the managing editors for major milestones; the other two components reset when it is bumped.
  • data is incremented every time a batch of database tables is pushed to production. Each push archives the changed tables on Zenodo, where every table has its own record with its own version number (major.minor, starting at 1.0) and a description of what changed; the data of any LMFDB version can be recovered from the corresponding Zenodo records.
  • code counts releases of the website code. Each release corresponds to a commit in the LMFDB git repository.

Versions up to and including 1.2.1 predate this scheme.
